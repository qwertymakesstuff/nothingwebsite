# SkinSpin (`/skinspin/`)

A case-opening simulator with original, fictional weapon skins and fictional coins. Plain HTML,
CSS and ES modules, no build step, no dependencies. Built in phases; done so far: **Phase 1**
(website foundation, item database and case catalogue, case opening, inventory).

Coins are play money only: there is no way to buy them or cash them out.

| File | Job |
| --- | --- |
| `index.html` | page shell: sidebar navigation, top bar (balance, level, inventory), view container |
| `css/style.css` | theme tokens, shell, buttons, item and case cards, modals, toasts |
| `css/views.css` | page styles: home, case page and roulette, inventory, profile, settings |
| `js/config.js` | tuning knobs: save key and version, starting coins, roulette timings |
| `js/rarities.js` | the seven rarity tiers and their colours |
| `js/wear.js` | wear tiers, float ranges, their chances and value multipliers |
| `js/items.js` | the item database (114 skins over 26 weapons and 8 types) and `itemValue()` |
| `js/cases.js` | the 15 cases: price, category, theme, collections, rarity weights, pools |
| `js/rewards.js` | `caseOdds()` (what the UI shows) and `rollCase()` (what is drawn), from the same data |
| `js/rng.js` | secure randomness for real rolls, seeded randomness for tests |
| `js/playerState.js` | the one player-state shape, levels and XP |
| `js/economy.js` | transactions: open, sell (single and bulk), lock, favourite, settings, refill |
| `js/save.js` | versioned `localStorage` save: load, migrate, repair, back up, write |
| `js/store.js` | the live game: runs transactions, saves after each, notifies views; the opener lock |
| `js/roulette.js` | strip building, landing geometry and time-based easing (no DOM) |
| `js/art.js` | original SVG artwork for every item and case, cached as data URIs |
| `js/main.js` | entry point: shell, hash router, top bar |
| `js/ui/*` | DOM helpers, icons, shared components, modal, toasts, synthesised sound |
| `js/views/*` | one module per page |

## Rules the code keeps

- Every transaction in `economy.js` validates first and mutates second, so a failed one changes
  nothing. Coins can't go negative, a sale can't include a missing, duplicated or locked item,
  and bulk sales skip favourites unless the player includes them.
- Opening a case charges, rolls and adds the item in one step **before** the roulette is built.
  The strip is laid out around that item and the animation only travels to it.
- The odds panel is generated by `caseOdds()`, which reads the same weights and pools `rollCase()`
  draws from. Each rarity's chance is split evenly between its items.
- The save is one JSON object with a `version`. Anything unreadable is copied to a backup key
  first; damaged fields are repaired one by one; saves from a newer version are backed up before loading.
